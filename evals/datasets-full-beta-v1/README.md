# Full beta evaluation source, version 1.5.0

> Public distribution note: links to internal historical plans and operational
> records are omitted here; the retained text describes the original decision or
> design.

This immutable input source contains all 21 required case families and binds all
71 historical AWS 0.30.0 definitions and their configuration schemas. It does
not contain observations, an evaluation report, promotion or hosted evidence.

The conflicting-requirements case now exercises intent.extract under the
Standard low-cost-extraction-help role. The private-network case requests
supported Lambda, private subnets, DynamoDB and a gateway endpoint with no
application generation. The image-processing case keeps the thumbnail business
implementation unresolved while requiring the supported S3/Lambda event
infrastructure to be recognized. All other historical family expectations and
all mandatory dimensions remain.

Historical datasets and operational budgets are unchanged. Current actual
provider observations, family validators, repair lineage, operational policy and
normal promotion still require completion under the active plan.

After building schemas and ModelGateway, run:

```sh
node evals/datasets-full-beta-v1/generate.mjs --check
```

The generator rehashes the actual historical catalog retained under
`packages/provider-aws/src/model-evaluation-source/` before comparing its exact
identity and each configuration schema/key. Its original bytes include the old
ALB definition and validation rules; filtering two WAF definitions out of the
current catalog cannot reproduce it. Current catalog drift requires a separately
reviewed source version; do not overwrite old frozen expectations after seeing a
provider result. The focused source test checks the historical mirror and
rejects the current catalog under this historical binding. The successor source
checks the current catalog independently.

Superseded source versions 1.0.0 through 1.3.0 remain in Git history (private
historical evidence, omitted from this distribution). They have no current
application, evaluation-command or report-policy reader. The focused tests
retain the current private-network and bounded-refusal operation-authority
checks without carrying full obsolete input mirrors.

Source 1.4.0 remains as the independent baseline for the event/external
successor regression: unchanged requirements, target dimensions and expected
issue severity are compared with the current dataset. Current 1.5.0,
authenticated 1.6.0 and typed planning 1.7.0 exports/mirrors retain their exact
source and policy commitments.

Typed bounded refusals still grant no mutation authority. Current admission
requires complete-envelope input counts and exact evaluation bindings; prior
token counts cannot establish it.

Source 1.4.0 replaces label-derived repository digests in four cases with the
actual checked UTF-8 files under repositories. Each source has a reproducible
synthetic Git commit identity; git hash-object verifies it without creating or
pushing a repository. These are fixed inputs, not outputs or hosted evidence.
Source 1.3.0 remains byte-for-byte in Git history. The actual importer and
pinned HCL parser retain unresolved confidence for the HCL declarations and do
not infer resources from the ambiguous TypeScript handler. Their local input
checks do not complete response validation, issue a live report or activate a
model.

## Authenticated API input successor 1.6.0

The separately named authenticated source changes only the basic API input to
require JWT authorization on every route and reject missing, invalid or expired
tokens. The owner selected the secure minimum-change approach on September 14.
All 20 other cases, expected outcomes, dimensions and catalog pins remain.

The original 1.5.0 export and mirror remain unchanged because existing report
policies bind those exact inputs. A global replacement was rejected by that
policy check before any provider invocation. The generator now checks both
mirrors. The authenticated input export grants no invocation, report or
promotion authority; adopting it requires a reviewed successor policy and fresh
exact input counts and evaluation evidence. Runtime routing, budgets and
historical approvals are unchanged.
